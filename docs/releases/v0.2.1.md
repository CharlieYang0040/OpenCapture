# OpenCapture v0.2.1 - 60 FPS Recording Stability

OpenCapture v0.2.1은 녹화 파일이 60fps로 표시되지만 실제 움직임은 낮은 프레임처럼
끊기거나 순간적으로 크게 멈추던 실시간 경로를 정리한 Windows x64 기술 프리뷰입니다.

## 주요 변경

- Windows Graphics Capture 콜백 실행 시각 대신 WGC 원본 `SystemRelativeTime`을 영상
  타임라인 기준으로 사용합니다.
- 녹화 처리를 ImGui/DXGI UI VSync에서 분리하고, 녹화 중 UI present가 캡처 소비 주기를
  제한하지 않도록 했습니다.
- 지연 뒤 빠진 모든 틱을 같은 화면으로 동기 재인코딩하던 catch-up loop를 제거하고,
  현재 PTS로 한 번에 이동해 순간 지연의 연쇄 증폭을 막습니다.
- 압축된 H.264/AAC 패킷은 2,048개 제한 비동기 mux 큐에서 MKV로 기록합니다. 종료 시
  큐를 먼저 비우고 trailer를 기록하며, 저장장치가 장시간 따라오지 못하면 명확히 실패합니다.
- WGC frame-ready event로 대기해 녹화 루프의 불필요한 1ms polling을 줄였습니다.
- 녹화 화면에 source FPS, 최대 source gap, WGC drop, skipped timeline ticks 및 mux queue
  peak를 표시해 캡처/GPU/저장장치 병목을 구분할 수 있습니다.
- WGC frame pool을 3개로 늘리고 리사이즈 재생성에도 같은 크기를 유지합니다.

## 자동 검증

- Visual Studio 2022, CMake, Ninja 및 pinned vcpkg 구성의 Debug/Release 빌드
- Debug/Release `opencapture_core_tests`, `opencapture_audio_tests`
- NVENC 및 OpenH264 각각에 대해 합성 320x180 60fps H.264 + AAC MKV mux 검증
- 패키지 manifest와 ZIP 재압축 해시 검증

사용자 요청에 따라 실제 화면/게임 녹화 테스트는 이번 배포 검증에서 제외했습니다.
따라서 게임 부하 중 1080p/1440p/4K 장시간 drop rate, 1% low 및 2시간 A/V drift는
확인되지 않은 수동 수용 기준으로 남습니다.

## 알려진 경계

- 하드웨어 인코딩은 GPU와 드라이버 지원 상태에 따라 NVENC, QSV, AMF, Media Foundation,
  OpenH264 순으로 가용성이 달라집니다.
- GPU crop/NV12 처리와 `avcodec_send_frame`은 아직 메인 실시간 경로에서 실행됩니다.
  별도 인코딩 스레드는 D3D11 immediate-context 동시성과 실제 게임 부하 검증 없이 넣을 경우
  오히려 프레임 손상이나 device hang을 만들 수 있어 이번 릴리스에는 포함하지 않았습니다.
- 실행 파일은 Authenticode 서명되지 않은 기술 프리뷰입니다.

## 설치

1. `OpenCapture-0.2.1-windows-x64.zip`과 `SHA256SUMS.txt`를 내려받습니다.
2. SHA-256을 확인하고 쓰기 가능한 폴더에 압축을 풉니다.
3. `OpenCapture.exe`를 실행합니다. 별도 설치 프로그램이나 관리자 권한은 필요하지 않습니다.
